Clash Verge下载这件事，结论只有一句：只去项目在 GitHub 上的 Release 页面拿安装包，别的渠道一律当作不可信。这篇把几件事讲清楚：现在大家说的 Clash Verge 其实是 Clash Verge Rev；Windows 与 Mac 的安装包怎么挑；Clash for Windows 为什么不再推荐；装好以后的第一步该做什么。

> **一分钟速查**
> - 入口：只认项目在 GitHub 上的 Release 页面，搜索广告、网盘和群文件里的安装包一律不碰；
> - 选包：先确认 Windows 是 x64 还是 arm64、Mac 是 Intel 还是 Apple 芯片，再对照 Release 页面实际列出的文件名；
> - 内核：安装包通常已内置 Mihomo 内核，不必另外下载替换；
> - 第一次使用：先导入订阅，模式选“规则”，打开系统代理跑通，TUN 以后再说；
> - 旧软件：还在用已停止维护的 Clash for Windows，订阅能用也建议找时间迁走。

## Clash Verge Rev 是什么，和 Mihomo内核是什么关系

Clash Verge Rev 是一个图形界面的代理客户端，能在 Windows、macOS 和 Linux 上运行。它本身是“壳”，真正负责转发流量的是内置的 Mihomo 内核（早期叫 Clash Meta）。三个概念分开理解，后面排错会轻松很多：

- **内核**：干活的引擎，读取配置，按规则转发流量；
- **客户端**：给引擎配的操作台，负责导入订阅、切换节点、开关系统代理和 TUN；
- **订阅**：机场给你的一条链接，客户端靠它拉取节点和规则，链接本身不在客户端里生成。

原版 Clash Verge 停更之后，社区接手的分支就是 Clash Verge Rev，所以现在搜到、聊到的 Clash Verge，基本指它。据项目说明，它的界面层用 Tauri 框架开发，依赖系统自带的网页渲染组件，这一点在后面的排错表里会用到。

内核和客户端的关系、Mihomo 的来龙去脉，在 [Mihomo Party 怎么用](/clients/mihomo-party/) 里有展开，这里不重复。

## Clash for Windows 为什么不再推荐

Clash for Windows（常简称 CFW）曾经是 Windows 上很常见的 Clash 客户端，但原作者已停止维护，原版 Clash 内核也不再更新。直接的后果有三个：

- 新出现的协议和订阅字段跟不上，部分节点可能读不出来，或者根本连不上；
- 出了 Bug 没人修，安全问题也没人跟进；
- 网上还留着大量 CFW 的老教程和“整合包”，其中一部分来路不明。

如果你还在用 CFW，订阅又能正常工作，不必今晚就慌，但建议找个周末迁走。迁移成本很低：订阅是机场给的，重新导入一遍就行；只有你自己手写的规则和覆写，需要在新客户端里重做。

## Clash Verge下载渠道：只认 GitHub 官方 Release

唯一推荐的入口是 [Clash Verge Rev 官方 Release 页面](https://github.com/clash-verge-rev/clash-verge-rev/releases)。打开以后核对三件事：

1. 域名是 github.com，仓库路径是 clash-verge-rev/clash-verge-rev，注意拼写，仿冒仓库常靠一两个字母的差别骗人；
2. 安装包在页面的 Assets（资源）列表里，类似 Source code 的源码压缩包不是安装包，列表太长时可能需要点开“显示全部”；
3. 新手选带 Latest 标记的正式版本，标着 Pre-release 的是预览版，留给愿意折腾的人。

这几类来源不要碰：搜索引擎广告位里的“官网”、网盘分享、群聊和论坛转发的安装包、写着“破解”“集成”“免费会员”的整合包。理由很朴素：客户端看得到你所有流量的去向，装上被改过的包，等于把家门钥匙交给陌生人。

下载完成后，如果 Release 页面给出了每个文件的校验值（如 SHA256），建议在本机算一遍再对照：

```powershell
Get-FileHash .\你下载的文件名 -Algorithm SHA256
```

macOS 的终端里对应的命令是：

```bash
shasum -a 256 ~/Downloads/你下载的文件名
```

两边对不上，就删掉重下，别将就。

## 安装包怎么选：Windows、Mac、Linux 对照表

选错最常见的原因不是“不会装”，而是 CPU 架构选反了。先确认设备，再看文件名：

| 你的设备 | 怎么确认 | 文件名里常见的标记 | 说明 |
|---|---|---|---|
| Windows 常规电脑 | 设置 → 系统 → 系统信息，看“系统类型”里是否为 x64 | x64，扩展名常见 exe 或 msi | 安装版是主流，部分版本还提供便携版压缩包 |
| Windows on ARM | “系统类型”写着基于 ARM 的处理器 | arm64 | 选成 x64 包可能无法运行或提示不兼容 |
| Mac（Apple 芯片） | 苹果菜单 → 关于本机，芯片显示为 Apple 开头 | aarch64 或 arm64，扩展名 dmg | 原生版本更合适 |
| Mac（Intel） | 关于本机里处理器显示 Intel | x64 或 x86_64，扩展名 dmg | Apple 芯片的包在 Intel 机器上无法运行 |
| Linux | 因发行版而异 | deb、rpm 等 | 以项目说明为准 |

文件名只是参考，一切以 Release 页面实际列出的文件为准。机场牛不写具体版本号，因为版本过一阵子就变，写了也会过期。

两个平台的系统层面细节，分别放在了专篇里：Windows 的管理员权限、杀毒软件和系统代理冲突，看 [Windows客户端教程](/clients/windows-jichang-kehuduan/)；Mac 的芯片确认和“无法验证开发者”放行，看 [Mac客户端教程](/clients/mac-jichang-kehuduan/)。

## 装好之后的第一步：导入订阅、选节点、再决定开不开 TUN

装好只是起点，没有订阅，客户端就是个空壳子。按这个顺序走最不容易乱：

1. 打开软件，找到类似“订阅”或“配置”的页面；
2. 把机场给的订阅链接粘贴进去，点导入，等待节点列表生成，逐步截图见 [Clash Verge导入订阅](/tutorials/clash-verge-daoru-dingyue/)；
3. 模式先用“规则”，不要一上来就开“全局”，两者区别见 [全局模式与规则模式](/glossary/global-vs-rule-mode/)；
4. 到类似“代理”的页面选一个节点，打开系统代理开关，再用浏览器验证；
5. 日常浏览够用就不必开 TUN。游戏、命令行工具这类不走系统代理的软件才需要它，开启步骤和常见坑见 [TUN模式设置](/tutorials/tun-mode-setup/)。

> 订阅链接等同于账号凭证，别发群里，别放进截图。泄露了怎么办，见 [机场订阅链接安全](/knowledge/dingyue-lianjie-anquan/)。

## 装了 Clash Verge Rev 还是用不起来：五个常见误区

下面五条，都是新手装 Clash Verge Rev 时容易冒出来的想法。每条按“误区、为什么不对、正确做法”拆开讲。

**误区一：搜到的第一个“官网”就是官网。**

- 为什么不对：搜索结果的排序靠的是投放和优化，不等于来源可靠。仿冒页面常常把下载按钮指向被改过的安装包，而代理客户端恰好能看到你全部的流量去向，这个口子不能开；
- 正确做法：直接打开项目在 GitHub 上的 Release 页面，核对仓库路径，只从项目自己的页面里取包。

**误区二：软件装好了，就能上网了。**

- 为什么不对：客户端本身不提供节点，节点来自订阅。没有订阅，装得再规范也只是个空壳。客户端是开源项目，真正要花钱的是机场订阅；
- 正确做法：先从机场面板复制订阅链接，再导入。订阅是什么、为什么要当密码保管，见术语页 [订阅链接](/glossary/subscription-link/)。

**误区三：预览版功能更多，直接装预览版。**

- 为什么不对：标着 Pre-release 的是预览版，可能带着还没被发现的问题。一旦出了怪毛病，你分不清是自己配错了，还是版本本身的问题；
- 正确做法：新手选带 Latest 标记的正式版。想尝鲜，先把正式版跑通、订阅备份好，再另外试。

**误区四：全局模式一直开，最省事。**

- 为什么不对：全局模式下所有流量都绕节点，国内站点也跟着绕，既多耗套餐流量，也可能让个别国内服务出现异常；
- 正确做法：日常用规则模式，全局只在排错时临时切一下，用来判断问题出在规则还是节点上。

**误区五：TUN 是“加强版系统代理”，开了更保险。**

- 为什么不对：[TUN模式](/glossary/tun-mode/) 是创建虚拟网卡，通常要管理员权限或服务组件，和杀毒软件、其他网络类软件更容易发生冲突。多数日常浏览，系统代理已经够用；
- 正确做法：先用系统代理跑通，确实遇到命令行、游戏这类不走系统代理的软件，再按 [TUN模式设置](/tutorials/tun-mode-setup/) 的步骤开启，并且一次只开一个客户端。

## Clash for Windows 迁移到 Clash Verge Rev：一个虚构案例的完整流程

下面的小 A 是虚构人物，情节只用来演示迁移的先后顺序，不对应任何真实用户，也不涉及任何测试数据。如果你对“订阅从哪来”还不熟，先看 [机场是什么](/knowledge/what-is-jichang/)。

小 A 用 Clash for Windows 用了很久，订阅一直能更新，所以没有动力换。直到有一天，他发现订阅更新后有几个节点读不出来了，网上能搜到的老教程也一个比一个对不上号。他决定周末把客户端换掉，过程是这样的：

1. **先不删旧软件**。他在旧客户端里把系统代理关掉，再退出程序，这样新旧两个软件不会抢系统代理；
2. **确认设备再下载**。他在系统信息里看到“系统类型”是 x64，于是打开官方 Release 页面，挑了对应的 Windows x64 安装包，页面有校验值，就在本机算了一遍核对；
3. **导入订阅，规则模式加系统代理**。装好后他把订阅链接粘贴进去，等节点列表出来，模式选“规则”，再打开系统代理，用浏览器验证能正常访问；
4. **补回自己写的规则**。他发现以前手写的几条规则不见了，因为那几条本来就不在订阅里。他翻出旧配置文件，在新客户端里用类似“合并”“覆写”的增强功能把它们加回去，一次只加一条，验证通过再加下一条；
5. **跑稳几天再卸载旧软件**。新客户端平稳用了一阵，他才把旧软件卸载，并顺手关掉旧软件留下的开机自启。

这个虚构案例想说明三件事。第一，迁移的成本主要只有两项：订阅重新导入，手写规则重做。第二，订阅链接是机场给的，不会因为换客户端而丢。第三，新旧客户端并存的那几天，一次只让一个在运行，导入试用本身不会让旧客户端失效，只要两个别同时开着系统代理。

## 现在就能做的三件事

1. 做 Clash Verge下载这一步时，只打开官方 Release 页面，按上面的表确认设备架构，再取对应的安装包；
2. 装好后不要急着开 TUN，先用规则模式加系统代理跑通一次，确认订阅和节点都正常；
3. 把订阅链接当密码保管，把本文收藏起来，下次重装系统直接照着走。

软件界面和功能会随版本变化，文中提到的名称与路径以软件实际显示和项目官方说明为准。使用代理服务请遵守所在地法律法规，机场牛不提供法律意见。
