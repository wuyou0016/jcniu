ChatGPT打不开，是用机场的人问得最多的问题之一，但“打不开”其实是三种完全不同的情况：页面加载不出来、能打开却被拒绝或反复验证、能登录却中途失败。先给结论，**别一上来就换节点，按“先本地、再订阅、后节点”的顺序查，每一层都有明确的判断办法**。这篇只讲方法：机场牛不会、也无法承诺任何节点或地区一定可用，地区支持情况以服务方官方公布的列表为准。

> 本文以网页版为主，适用于大多数 AI工具，其他服务的域名和支持地区各不相同，以对应的官方说明为准。

## ChatGPT打不开，先分清是哪一种打不开

对号入座，能直接决定你该从哪一层查起：

| 你看到的现象 | 说明什么 | 先查哪一层 |
|---|---|---|
| 页面空白、一直转圈、加载一半 | 部分域名没走代理，或请求被中途切断 | 本地层：规则、DNS、浏览器 |
| 提示所在地区不受支持（类似 not available in your country 的英文提示） | 出口地区不在官方支持范围，或出口并不是你以为的地方 | 节点层：核对出口 |
| 反复要求确认你是真人，或直接拒绝访问 | 出口 IP 被风控标记，或验证环境不完整 | 节点层，再回本地层 |
| 能登录，但发送消息失败、回答说到一半断了 | 连接不稳或被中途切断 | 节点层，再看是否有自动切换 |
| 登录时提示账号被限制或需要额外验证 | 账号层问题，和网络无关 | 官方帮助中心 |

## 先确认服务本身，再动手改设置

1. **看官方的服务状态页**，入口在官方站点的页脚或帮助中心。服务本身出故障时，换什么节点都没用，白折腾。
2. **用另一个设备或另一种网络对照**，比如手机热点下的另一台设备。别的设备正常，问题就在你这台设备上。
3. **对照其他 AI工具和境外网站**。别的境外站点正常、只有它打不开，更偏向目标服务的判断；全部境外站点都不行，回到连接问题，看 [已连接但无法上网](/troubleshooting/yilianjie-dan-meiwang/)。

## 本地层：浏览器、客户端和分流规则

大部分“打不开”死在这一层，而且修复成本最低。

### 浏览器环境，五项逐个排除

- **无痕窗口**：默认通常不加载扩展，也不带旧缓存，是最省事的对照；
- **清除该站点的缓存和 Cookie**：只清这个站点，别清全部，免得影响其他登录状态；
- **停用扩展**：广告拦截、隐私保护、脚本拦截、请求头修改类的扩展，都可能拦掉验证脚本；
- **安全 DNS 设置**：浏览器自带的加密 DNS 可能绕开客户端的 DNS，在虚拟网卡模式下会让客户端看不到域名，分流规则就按 IP 去匹配，对照时先关掉它；
- **系统时间**：偏差大会引发证书和验证错误，设成自动同步。

### 分流规则：页面不是一个域名

一个页面往往要加载多个域名的资源，包括登录、静态文件、验证脚本。**只有主域名走了代理，其余走了直连，就会表现为转圈或登录循环**。办法如下：

1. 在浏览器里按 F12，打开开发者工具里类似“网络”的面板，刷新页面；
2. 找出红色的失败请求，记下它们的域名；
3. 到客户端的连接页，看这些域名命中了哪条规则、走了直连还是节点；
4. 命中直连的，在规则里补上，写法见 [分流规则怎么设](/tutorials/mihomo-fenliu-guize/)，补完后重新加载配置再测。

域名组成会随服务更新而变，所以别抄别人的域名清单，以你自己在网络面板里看到的为准。

### 自动选择、IPv6 和 DNS

- **自动切换出口的策略组**：自动选择、负载均衡类策略组，可能在你使用期间悄悄换了出口。验证过程中 IP 变了，表现就是反复验证。对 AI 相关域名，固定一个节点更稳妥；
- **IPv6**：有的网络环境里，IPv6 流量没被接管，服务看到的是你的本地出口。对照时可以先关掉系统的 IPv6，看是否有变化，测完记得还原；
- **DNS 与 TUN**：怀疑域名没走代理，用 [DNS泄漏检测](/tutorials/dns-xielou-jiance/) 的方法核对，再用 [TUN模式设置](/tutorials/tun-mode-setup/) 做一次对照。

## 订阅层：节点列表和流量状态

本地都正常、ChatGPT打不开的情况依旧，再看订阅：

1. **订阅是否过期、流量是否用尽**。到期或用尽后节点还在列表里，但服务端已经不放行；
2. **订阅是否太旧**。服务商调整过线路，你本地的节点可能早已下线，更新一次订阅，更新失败看 [订阅更新失败怎么办](/troubleshooting/dingyue-gengxin-shibai/)；
3. **更新后节点名称变了**。节点名里的地区只是机场自己的标注，别拿它当事实，下一步要核对出口。

## 节点层：出口地区与 IP 怎么核对

最后才轮到节点，核对顺序如下：

1. **核对出口 IP**：连上节点后，用 IP 查询页看国家、城市、运营商。不同查询页的数据库可能不一致，多查几个；
2. **对照官方支持地区**：看服务方公布的列表，出口不在列表里，换到列表内的地区；列表会更新，以官方页面为准，本文不列具体地区；
3. **同地区换一个节点**：换节点等于换出口 IP，不是换地区。只有个别节点打不开，多半是那个 IP 的问题；
4. **关注 IP 类型**：被识别为机房或代理的 IP，更容易触发验证，原生 IP 的概念和验证办法见 [原生IP机场怎么看](/guides/yuansheng-ip-jichang/)；IP 类型只是风控的一项输入，不是开关；
5. **别拿延迟当可用性**：延迟低只说明握手快，不说明能访问。

> 机场牛不提供“哪个节点能用”的清单。能不能访问由服务方的策略决定，且持续变化，只有你自己核对出口、自己验证的结果，才是当下有效的依据。

## 五个场景对号入座：你的打不开属于哪一种

前面按层排查是“从上往下走”，这里换成“从现象反推”。找到最像你的那一个，直接去做对应动作，再回到分层清单补漏。以下只讲方法，不涉及任何节点或地区的可用性承诺。

- **如果你的页面一直转圈或加载一半**：多半是页面依赖的某些域名没走代理，或者被浏览器扩展拦掉了。先用无痕窗口对照；还是转圈，就在开发者工具的网络面板里找出失败请求的域名，回到客户端的连接页看它们命中了什么规则，缺哪条补哪条。这个阶段不需要换节点。
- **如果你看到“所在地区不受支持”一类的提示**：先别猜，用 IP 查询页核对当前出口的国家和城市，再对照服务方官方公布的支持地区列表，列表以官方页面为准。出口本来就在列表里，换节点多半没用，应该回头查 IP 查询页的结果是否一致、是否有出口在中途切换；出口不在列表里，才有换出口的理由，这时可以参考 [落地节点](/glossary/exit-node/) 的概念，理解“你看到的出口”究竟是哪一台服务器。
- **如果你反复被要求确认是真人**：验证过程要求环境前后一致，所以先固定一个节点，别让策略组自动切换；再用无痕窗口、停用扩展、校准系统时间。这些都做完仍然反复验证，更可能是出口 IP 本身被服务方判定为可疑，同地区换一个节点再试，不要连续高频刷新。
- **如果你能登录，但发消息失败或回答说到一半就断**：这类长时间保持的连接，对网络稳定性更敏感。检查自动选择、负载均衡类策略组有没有在你使用时切换出口，固定节点后对照；如果日志里大量出现超时，去走 [机场节点超时怎么办](/troubleshooting/jiedian-quanbu-chaoshi/) 的清单。
- **如果你只在某个网络下打不开，换网络就好了**：公司、学校等网络可能对流量有自己的管理策略，这种环境以网络管理员的规定为准，别自己硬绕。回到家里的网络若一切正常，说明问题多半不在节点、订阅这一层。

## ChatGPT连不上，十项可勾选的自查清单

下面这份清单对应上面的分层顺序。每做完一项，在方框里打勾；一次只改一个变量，改完测一次，把结果记进文末的排查表。

- [ ] 打开官方的服务状态页，确认服务本身没有公布的故障
- [ ] 用手机热点下的另一台设备访问一次，作为对照
- [ ] 用无痕窗口访问一次，排除缓存和扩展的影响
- [ ] 只清除这个站点的缓存和 Cookie，没有清除全部浏览数据
- [ ] 停用广告拦截、隐私保护、脚本拦截、请求头修改类扩展，逐个恢复以定位
- [ ] 暂时关闭浏览器自带的安全 DNS，并确认系统时间已自动同步
- [ ] 在网络面板里记下失败请求的域名，到客户端连接页确认每个域名走了哪条规则
- [ ] 把相关域名固定到同一个节点，而不是交给自动选择或负载均衡
- [ ] 用两个以上的 IP 查询页核对出口国家和城市，再对照官方公布的支持地区列表
- [ ] 手动更新过订阅，确认套餐未到期、流量未用尽

十项都打了勾，仍然打不开，你手里至少有一份完整的记录：哪些排除了、哪些没排除、出口显示在哪里。把它整理好，不管是去问机场客服，还是去官方帮助中心，沟通效率都会高很多。记得发出去之前，把订阅链接和账号信息打码。

## ChatGPT连不上的五个常见误区

很多人折腾半天没结果，不是技术不够，而是排查方向一开始就偏了。下面五条误区，每条给出“为什么不对”和“正确做法”。

1. **误区：“节点名字写着某个地区，出口就一定在那个地区。”**
   - 为什么不对：节点名里的地区是机场自己的标注，不是事实证明；出口的国家和城市，要连上之后用查询页核对。
   - 正确做法：以 IP 查询页显示的出口为准，并且多查几个页面，数据库不同，结果可能不一致。

2. **误区：“换了节点还是不行，说明这个服务封了我。”**
   - 为什么不对：换节点只是换出口 IP，换不掉本地的浏览器扩展、规则缺失、安全 DNS 这些因素。
   - 正确做法：先用无痕窗口和另一台设备对照，确认本地层干净之后，再谈节点。

3. **误区：“把浏览器数据全部清掉最保险。”**
   - 为什么不对：全清会让其他网站的登录状态一起丢失，而且问题往往并不出在缓存上。
   - 正确做法：只清这个站点的缓存和 Cookie，先用无痕窗口验证是不是缓存的问题。

4. **误区：“网上有人说某个节点能用，我照着买、照着选就行。”**
   - 为什么不对：服务方的风控策略和支持地区会变化，某个时间点的结果推不到下一周，更不能推到你的网络环境上。
   - 正确做法：学会自己核对出口、自己验证。选购时先看 [机场推荐排行榜](/rankings/) 里的资料，把它当起点，不要当承诺。

5. **误区：“一直刷新、一直重试，总有一次能进去。”**
   - 为什么不对：短时间高频重试，可能让验证更频繁；你自己的变量也在变，反而说不清是哪一次改动起了作用。
   - 正确做法：停下来，固定一个节点、一个浏览器环境，改一个条件，只测一次，记下结果，再改下一个。

## ChatGPT连不上还是账号问题：什么时候该停手

下面这些，换节点解决不了：

- 提示账号被限制、需要额外验证、付款相关错误；
- App 在应用商店里搜不到、装不上，这是应用商店地区的问题，以官方和商店说明为准；
- 服务本身故障。

这类问题去官方帮助中心处理。也别为了“解锁”去买来路不明的账号或共享账号，安全和合规风险都在你自己身上。使用 AI 工具请遵守服务条款和所在地法律法规，机场牛不提供法律意见。

## 其他 AI工具打不开，同样套用这份清单

换成别的 AI 服务，步骤不变：先看服务状态，再查本地、订阅、节点，只是域名和支持地区要换成对应服务的。开发者场景里命令行、IDE 和 API 调用的网络要求不同，见 [AI开发环境网络怎么搭](/guides/claude-ai-gongju-jichang/)。

## 术语速查：排查 AI 工具打不开时的几个词

读排查文章时，这些词会反复出现，认一遍，后面看别的教程也轻松。

| 术语 | 一句话解释 | 在排查里的用处 |
|---|---|---|
| 出口 IP | 服务方看到的、你访问它时使用的地址 | 核对它的国家和城市，是判断“地区不受支持”的起点，见 [落地节点](/glossary/exit-node/) |
| 原生 IP | 由当地运营商分配的一类 IP，常与机房 IP 对比 | 只是风控参考的一项输入，不是通行证，见 [原生IP](/glossary/native-ip/) |
| 策略组 | 客户端里把多个节点打包、自动或手动选择的功能 | 自动选择可能中途换出口，验证时要固定 |
| 分流规则 | 决定哪些域名走代理、哪些直连的规则 | 页面有多个域名时，漏掉一个就会转圈，写法见 [分流规则怎么设](/tutorials/mihomo-fenliu-guize/) |
| 安全 DNS | 浏览器自带的加密域名解析 | 可能绕开客户端的 DNS，对照时先关闭 |
| TUN 模式 | 通过虚拟网卡接管整机流量的模式 | 域名走不走代理拿不准时，做一次对照，见 [TUN模式](/glossary/tun-mode/) |
| 风控 | 服务方判断访问是否可疑的一整套策略 | 外部看不到细节，所以不要迷信“某个 IP 一定可用” |

这些词里最重要的是前两个：出口 IP 决定服务方怎么看你，分流规则决定你的流量到底从哪里出去。把这两样搞清楚，大多数“打不开”的原因你都能自己判断，不需要靠别人给的节点清单。

| 2 | 停用扩展 | 通 / 不通 |
