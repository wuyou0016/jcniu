faqs:
  - q: 订阅链接导入失败，一定是格式不对吗？
    a: 不一定。格式不匹配只是原因之一，更常见的是链接被重置、套餐过期、复制时少了一截，或者订阅域名从本机直连不通。建议先用浏览器打开链接，看返回的是文本、下载文件还是报错页，再判断要不要转换，别一上来就找转换工具。
  - q: 在线转换服务会看到我的上网内容吗？
    a: 一般来说不会。转换服务只经手订阅配置，不在你的上网流量路径上。但它能看到订阅链接和里面的服务器地址、密码等信息，这些足够让别人冒用你的节点。所以风险在凭证，不在浏览记录，转换后最好能重置链接。
  - q: Clash 能直接用通用订阅吗，不转行不行？
    a: 视客户端和内核版本而定。部分 Clash 系客户端或 Mihomo 内核能识别通用订阅里的节点分享链接，但不带策略组和规则，使用体验和完整的 Clash 订阅不同。能否直接导入，以所用客户端的官方说明为准，更稳妥的办法是亲手导入一次试试。
  - q: 转换之后原来的流量信息为什么不显示了？
    a: 客户端显示的已用流量和到期时间，通常是机场在返回订阅时附带的信息。转换服务不一定会把这部分信息原样带过来，于是卡片上就空了。这不影响节点使用，想看真实用量，请登录机场的用户面板，以面板为准。
  - q: 转换后的链接泄露了怎么办？
    a: 把它当成原订阅链接泄露来处理：登录机场面板，找类似重置订阅链接的功能，生成新链接，旧链接立即失效，再用新链接重新导入。因为转换后的链接里通常带着原订阅地址，只删掉转换页面里的记录是不够的。

订阅转换，就是把机场给你的订阅内容，转成你的客户端读得懂的格式。结论先给：能不转就不转，先去机场面板找有没有对应格式的入口；真要转，别把链接随手交给不认识的在线服务，转完还要检查节点有没有被漏掉。这篇讲清三种常见格式、什么时候需要转、六步怎么做，以及转换会带来哪些风险。

> 文中的链接和命令都是占位示例，不是真实订阅。软件界面一律写成“类似……”，请按位置和含义去找。

## 订阅格式有几种：通用 base64、Clash YAML、sing-box JSON

订阅链接（概念见 [订阅链接是什么](/glossary/subscription-link/)）本质上是一个网址，访问它会拿到一份节点清单。清单的写法不止一种：

| 格式 | 打开后长什么样 | 常见使用者 | 特点 |
|---|---|---|---|
| 通用订阅 | 一大串看不出含义的字符，解码后每行一个节点分享链接，开头是协议名加冒号斜杠 | v2rayN、Shadowrocket 这类客户端通常能直接读 | 只有节点，没有分组和规则 |
| Clash YAML | 纯文本，能读到 proxies、proxy-groups、rules 这些字段 | Clash Verge Rev、Mihomo Party 等 Clash 系 | 节点、策略组、规则一起带 |
| sing-box JSON | 花括号包起来的 JSON，里面有 outbounds 等字段 | sing-box 系客户端 | 同样能带分组与路由 |

除此之外，还有一些客户端使用自己的配置写法，这里不展开。一份 Clash订阅格式 的骨架长这样，全部是示意：

```yaml
proxies:                    # 示意：节点清单
  - name: "示例节点-01"
    type: trojan            # 协议类型
    server: node.example.com
    port: 443
    password: "占位密码"
proxy-groups:               # 示意：策略组，把节点包成可选项
  - name: "手动选择"
    type: select
    proxies: ["示例节点-01"]
rules:                      # 示意：分流规则，自上而下匹配
  - MATCH,手动选择
```

三者的差别可以这么记：通用订阅像一张名片夹，只有联系方式；Clash 和 sing-box 的格式更像一份完整的行程单，连“怎么走”（分组和规则）都写好了。各协议本身的区别，见 [VLESS Trojan Hysteria2区别](/knowledge/vless-trojan-hysteria2-bijiao/)，它决定了转换时哪些节点可能被漏掉。

## 什么时候需要转，什么时候不需要

先用这张表对号入座：

| 你的情况 | 要转吗 | 怎么办 |
|---|---|---|
| 机场面板里有对应你客户端的订阅入口 | 不用 | 直接复制那一条 |
| 客户端能直接导入机场给的链接 | 不用 | 导入后看节点是否齐全 |
| 机场只给一种格式，客户端不认 | 需要 | 看下文六步 |
| 同一份订阅要给几种客户端用 | 视情况 | 优先让面板分别给各客户端的链接 |
| 只是想改规则、加一个策略组 | 不用转 | 用客户端的覆写或扩展配置功能，见 [分流规则怎么设](/tutorials/mihomo-fenliu-guize/) |

有三个常见误会，先排除：

1. **导入失败不等于格式问题**：链接失效、套餐过期、网络不通都会导致失败，先看 [订阅更新失败怎么办](/troubleshooting/dingyue-gengxin-shibai/)；
2. **节点列表为空不等于要转换**：多半是套餐状态或链接被重置；
3. **想要“更好的规则”不等于要转换**：改规则有更安全的办法，没必要把链接送出去。

## 订阅转换教程：六步照着做

1. **先看你手里是什么格式**
   - 做法：在终端里只看订阅内容的开头，命令如下，链接是占位，换成你自己的：

   ```bash
   curl -s "https://example.com/sub/你的订阅令牌" | head -c 120
   ```

   - 预期：看到一串连续的、读不出含义的字符，通常是通用订阅；开头能读到 proxies: 就是 Clash YAML；开头是花括号就是 JSON。
   - 出错：返回的是一个网页或登录提示，说明链接本身有问题，不是格式问题。另外要注意，有的机场会根据请求的客户端标识或链接里的类型参数返回不同格式，终端里看到的未必和客户端拿到的一样。
   - 提醒：只看开头，别把完整输出发给任何人，里面是你的节点凭证。

2. **确认客户端要什么**
   - 做法：翻你所用客户端的官方说明，看它支持哪几种订阅格式。Clash 系客户端的选择见 [Clash机场推荐](/guides/clash-jichang-tuijian/)。
   - 预期：得到一句明确的结论，比如“需要 Clash 格式”。

3. **先去面板找原生入口**
   - 做法：登录机场用户面板，找订阅或类似“客户端配置”的区域，看有没有按客户端分开的复制按钮。
   - 预期：能找到你客户端对应的那一条，到这里就不用转了。
   - 出错：只有一个通用入口，就问机场客服有没有对应格式。联系客服时只在机场的工单里提，别发到公开群。

4. **试试让客户端直接读**
   - 做法：把链接按 [Clash Verge导入订阅教程](/tutorials/clash-verge-daoru-dingyue/) 的步骤导入一次。
   - 预期：节点正常出现，就不需要转。
   - 出错：提示格式不对、节点为空，再进入下一步。

5. **必须转时，选转换方式**
   - 做法：按下面这张表，优先选风险小的：

   | 方式 | 订阅链接去了哪 | 门槛 | 适合谁 |
   |---|---|---|---|
   | 机场提供对应格式 | 不外传 | 低 | 所有人，首选 |
   | 在自己电脑或服务器上运行开源转换程序 | 只在你自己的机器里 | 较高 | 会用命令行、愿意看项目说明的人 |
   | 第三方在线转换服务 | 交给对方服务器 | 低 | 没有别的办法，且接受风险的人 |

   - 预期：选定方式后，得到一份目标格式的订阅或配置文件。
   - 说明：本地转换程序的名称和命令因项目而异，按其官方说明操作，不会用就别硬上。

6. **转完立刻检查**
   - 做法：导入客户端，对照机场面板核对节点数量、地区、协议种类，再切到规则模式试几个站点。
   - 预期：节点基本齐全，能正常访问。
   - 出错：见下文“转换之后常见的五个问题”。

## 订阅转换安全：交给第三方，对方到底看到什么

使用第三方在线服务时，你交出去的有这几样东西：

- **订阅链接本身**：里面的令牌就是账号凭证，概念见 [机场订阅链接安全](/knowledge/dingyue-lianjie-anquan/)；
- **订阅内容**：服务器地址、端口、密码或 UUID，这些是你用节点的全部凭据；
- **转换后的新链接**：通常会把原订阅地址当作参数带在里面，拿到新链接，等于拿到原链接；
- **你的使用习惯**：对方能看到有人在何时拉取了配置。

要澄清一点：转换服务一般只经手配置，不经手你的上网流量，所以它看不到你访问了什么。风险集中在凭证被冒用：流量被盗刷、设备数超限，严重时账号被封。

| 风险 | 后果 | 降低办法 |
|---|---|---|
| 链接泄露或被滥用 | 流量被他人消耗 | 转换前先确认面板里有重置订阅的功能，不满意随时重置 |
| 转换服务下线或限流 | 以后更新订阅失败 | 对关键设备，优先用机场原生格式 |
| 来路不明的规则模板 | 分流和 DNS 被人改写 | 只用你看得懂的模板，不要导入陌生人发来的配置 |
| 转换器不认新协议 | 节点被悄悄丢掉 | 转后对照面板的节点清单 |

更稳妥的做法按顺序是：机场原生格式优先；其次本地转换；实在要用在线服务，就用一条你随时愿意重置的链接，确认网址是 https，用完看情况重置，转换后的新链接也不要发到公开场合。

## 转换之后常见的五个问题

| 现象 | 常见原因 | 怎么办 |
|---|---|---|
| 节点比面板上少 | 转换器不认较新的协议或参数，直接丢掉 | 对照面板节点清单，换来源或换方式 |
| 流量和到期时间不显示 | 用量信息靠原订阅附带，转换服务不一定透传 | 到面板查看，不影响使用 |
| 规则和预期不一样 | 转换时套用了对方的规则模板，而不是机场的 | 改用覆写自己控制规则 |
| 过一阵更新失败 | 转换服务下线，或原链接已被重置 | 先确认原链接可用，再换方式 |
| 节点名字被改得奇怪 | 转换时开了重命名或加标记的选项 | 关掉相关选项重新转换 |

规则模板这一项值得多说一句：模板里的规则集如果托管在对方的服务器上，每次规则更新都会向对方发请求，对方不在线，规则就拉不下来。

## 进阶：转换器在背后做了什么，哪些东西会在转换里丢掉

把转换器想成一台“翻译机”，它通常分三步干活。

**第一步，拉取并解析原订阅。** 把每个节点拆成结构化的信息：协议类型、地址、端口、凭据、传输参数。**第二步，按目标格式重新排列。** 目标是 Clash，就写进 proxies；目标是 sing-box，就写进 outbounds。**第三步，套一份模板。** 目标格式比通用订阅多出来的策略组和规则，来自转换器或转换服务自带的模板，而不是机场写的。

这三步直接解释了转换后最常见的几种状况：

- **节点比面板少**：第一步靠转换器对协议和参数的认识，认不出的新协议或不常见参数，会被丢掉或者写错。
- **规则和预期不同**：第三步用的是对方的模板，你以为在用机场的规则，其实是别人写的。
- **转换后的链接更新失败**：常见的在线服务是动态转换，每次客户端更新，对方都要再去拉一次原订阅。所以转换服务必须持续持有你的原链接，它下线、限流，或者原链接被重置，转换后的链接都会一起失效。

最后一点是安全上的关键：既然对方持续持有原链接，**重置订阅链接就是你手里最后、也最有效的止损手段。** 转换前先确认面板里有这个功能，知道它在哪。这只是常见实现的一般性描述，不同转换程序差异很大，请以所用项目的官方说明为准。订阅链接在更大范围里的风险，读 [机场订阅链接安全](/knowledge/dingyue-lianjie-anquan/) 和 [机场安全吗](/warnings/jichang-anquan-yinsi/)。

## 关于订阅转换的 5 个常见误区

**误区 1：在线转换的网址是 https，就等于安全。**
为什么不对：https 只负责你到对方服务器这一段的加密传输，不管对方怎么保存、怎么处理你交出去的链接。正确做法：把“对方是否可信”和“传输是否加密”分开看，链接交给谁，比用什么协议传输更重要。

**误区 2：转换之后，原链接就可以丢掉了。**
为什么不对：动态转换依赖原链接，原链接被重置，转换后的链接也会失效。正确做法：原链接仍要妥善保存，而且它是你最重要的凭证。

**误区 3：转换一次就一劳永逸。**
为什么不对：机场调整节点或协议、转换程序升级，都可能改变结果。正确做法：每次机场公告调整后，把转换后的节点数量和面板对照一遍。

**误区 4：转换之后规则会更好用。**
为什么不对：规则好不好取决于模板，不取决于“转换”这个动作。多数时候，你想要的只是改几条规则。正确做法：想改规则就用客户端的覆写功能，不需要把链接送出去，写法见 [分流规则怎么设](/tutorials/mihomo-fenliu-guize/)。

**误区 5：别人分享的现成转换链接和配置，拿来就用最省事。**
为什么不对：里面是别人的规则和 DNS 设置，可能被改写，把你的流量导向不想要的地方。正确做法：来源说不清的配置不导入，要用就用自己看得懂的模板。

## 转换前后，逐项勾选这 10 条

**转换之前：**

- [ ] 我已经用终端或浏览器只看了订阅返回内容的开头，判断了格式，没有把完整内容发给任何人。
- [ ] 我在机场面板里找过按客户端分开的订阅入口。
- [ ] 我把原链接直接导入客户端试过一次，确认真的读不出来。
- [ ] 我确认面板里有重置订阅链接的功能，并且知道在哪。
- [ ] 我选了风险最小的方式：原生格式优先，其次本地转换，最后才是在线服务。

**转换之后：**

- [ ] 节点数量、地区、协议种类，和面板上的清单核对过。
- [ ] 规则模式下试了几个常用站点，访问都正常。
- [ ] 转换后的新链接没有出现在群聊、截图或公开笔记里。
- [ ] 如果用了在线服务，我决定了用完之后要不要重置原链接，并写进了日历。
- [ ] 如果用的是 Clash Verge、v2rayN 或小火箭，我对照过各自导入教程里的预期结果：[Clash Verge导入订阅](/tutorials/clash-verge-daoru-dingyue/)、[v2rayN导入订阅](/tutorials/v2rayn-daoru-dingyue/)、[小火箭导入订阅](/tutorials/shadowrocket-daoru-dingyue/)。

## 今天就做：三步判断要不要转

1. 登录面板，先找有没有你客户端对应的订阅入口，有就用，到此为止；
2. 没有的话，用上面的第 1 步和第 4 步判断客户端能不能直接读；
3. 必须转的，选本地方式或可随时重置的方案，转完核对节点。挑机场时，也可以把“是否提供对应格式的订阅”当作一项加分，去 [机场推荐排行榜](/rankings/) 对照资料后再决定。

软件界面、订阅格式和配置字段会随版本变化，以项目官方说明和软件实际显示为准。使用代理服务请遵守所在地法律法规，机场牛不提供法律意见。
