Clash机场推荐这件事，先说结论：“支持 Clash”几乎不是挑机场的门槛。主流机场基本都能给出 Clash 能读的订阅，真正拉开差距的是协议、线路、订阅的更新方式和售后。这篇先理清 Clash 家族现在谁还在维护，再给出挑机场的 4 个判断点，最后教你拿到订阅后怎么逐项核对。页面下方的数据块只列资料里明确标注了 Clash 支持的品牌，数量不多，原因在后面单独讲。

## Clash 这个词到底指什么，现在谁还在更新

“Clash”在圈子里同时被当成三样东西来用，混在一起是很多误会的源头：

- **内核**：真正负责转发流量的程序。最早的 Clash 内核已经停止维护，后来的主流延续者是 Mihomo（原名 Clash Meta）。
- **图形客户端**：套在内核外面、给你点按钮的软件。Clash for Windows 已停止维护，不建议新装；仍在更新的有 Clash Verge Rev、Mihomo Party 等。
- **配置格式**：一份 YAML 文件，里面有节点列表（proxies）、策略组（proxy-groups）和规则（rules）。如今不少客户端都能读这种格式，哪怕名字里没有 Clash。

| 名称 | 角色 | 说明 |
|---|---|---|
| Clash for Windows | 旧图形客户端 | 已停止维护，不建议新装 |
| Clash Verge Rev | 跨平台图形客户端，内核基于 Mihomo | 社区持续维护，只走官方仓库的 Release 下载 |
| Mihomo | 内核，原 Clash Meta | 持续维护，协议支持随版本更新 |
| Mihomo Party | 另一款以 Mihomo 为内核的图形客户端 | 特点与取舍见 [Mihomo Party 怎么用](/clients/mihomo-party/) |

维护状态会变，官方仓库在这里：[Clash Verge Rev 的 Release 页面](https://github.com/clash-verge-rev/clash-verge-rev/releases)、[Mihomo 内核仓库](https://github.com/MetaCubeX/mihomo)。名字里带 Clash 的 App 很多，各平台还有第三方实现，质量参差，安装包只认官方仓库或所在平台的官方应用商店。Windows、macOS 上的安装包怎么选，见 [Clash Verge 下载与安装](/clients/clash-verge/)。

## 为什么“支持 Clash”不是门槛

Clash 读的是一份配置，而不是某个机场的专属接口。机场后台通常有几种做法：有的按客户端自报的标识返回不同格式，有的在面板里分别给出通用订阅和 Clash 订阅两个地址，有的只给通用订阅，让你自己转。

就算机场没给 Clash 格式，你也能转换得到——只是转换意味着订阅链接要经过一道手。关于转换的风险和更稳的做法，单独写了一篇：[订阅转换是什么、有哪些风险](/tutorials/dingyue-zhuanhuan/)。

所以宣传里的“支持 Clash”，只说明有现成格式，并不说明线路更好、更便宜、更靠谱。拿它当筛选条件，等于用“有没有 Word 文档”来挑律师。

## Clash机场推荐的 4 个判断点

### 判断点 1：订阅格式，是原生提供还是要你自己转

优先选**明确写了 Clash/Mihomo 订阅地址**的机场。原生输出的好处是节点命名、策略组、分流规则都由机场自己维护，出问题时客服也能直接对照。靠转换得到的配置，出了问题就要先判断是机场的锅还是转换工具的锅。

### 判断点 2：协议要和内核版本对得上

节点用什么协议，客户端的内核认不认，是导入后“节点是空的”或“某些节点连不上”的常见原因。VLESS、Trojan、Hysteria2 等协议的设计思路和对客户端的要求，可以看 [VLESS、Trojan、Hysteria2 的区别](/knowledge/vless-trojan-hysteria2-bijiao/)。实操上记住两点：

- 内核太旧会遇到不认识的协议类型，通常表现为节点被跳过或报错。
- 较新的协议是否支持，取决于你用的内核和客户端版本，以项目官方说明为准。

### 判断点 3：线路与节点资料，才是体验的大头

客户端只决定“怎么连”，线路决定“连得怎么样”。线路类型、节点地区分布、运营时长、退款条款，这些和 Clash 没有关系，但占了体验的大头。总纲看 [机场怎么选的 5 步法](/guides/jichang-zenme-xuan/)，横向比较看 [机场推荐排行榜](/rankings/) 和 [机场对比](/compare/)。这一步别偷懒，不然就是给好车配了条烂路。

### 判断点 4：配置能不能自己改，改了会不会被更新冲掉

机场下发的配置自带策略组和规则。你想加自己的规则，比如让某些域名走固定节点，通常有两条路：用客户端提供的覆写、脚本类功能，或者在本地直接改文件。直接改文件的问题是下次订阅更新就可能被覆盖。分流规则的写法见 [分流规则入门](/tutorials/mihomo-fenliu-guize/)。另外看一眼机场有没有 Clash 使用文档、客服是否懂这套东西，这比“节点数量”靠谱得多。

## 按场景对号入座：5 种 Clash 用户怎么挑机场

同样是用 Clash，处境不同，挑机场时该盯的东西也不同。下面 5 个场景，找到最像你的那一个。

**如果你是第一次接触 Clash 的新手**，优先选面板里明确给出 Clash 或 Mihomo 订阅地址的机场，并且先买月付。原因很直接：新手最容易卡在“导入失败”这一步，原生格式能砍掉一半排查成本，月付则让你在验证期内还有退路。客户端先装一个仍在维护的，再照着教程导入。

**如果你是从 Clash for Windows 迁移过来**，不要急着把旧配置整份搬进新客户端。旧版停更后，内核和配置字段都有变化，整份照搬可能出现字段不识别。更稳的做法是：保留旧版不动，装好新客户端，只导入机场的订阅，跑通之后再把你自己写的规则一条一条挪过去。

**如果机场只给你一份通用订阅**，先向客服要原生 Clash 格式的地址，要不到再考虑本地转换。转换意味着订阅链接要经过一道手，风险和做法见 [订阅转换是什么、有哪些风险](/tutorials/dingyue-zhuanhuan/)。这种情况下也要留意：转换后的策略组和规则是工具生成的，出了问题要多分一步判断是谁的锅。

**如果你有多台设备**，先看套餐允许的同时在线设备数，再确认每台设备上的客户端都能读这份配置。电脑端和手机端的客户端对格式的支持面不一样，别只在一台机器上试完就下结论。同一份订阅跨平台使用时，更新间隔不要设得太短。

**如果你想自己改分流规则**，挑机场时要看两点：配置里的策略组是不是你能理解的结构，客户端有没有覆写类功能，能让你的修改在订阅更新后保留下来。规则怎么写、策略组怎么分，见 [分流规则入门](/tutorials/mihomo-fenliu-guize/)。机场的节点再多，规则一团乱也会让你越用越烦。

## Clash订阅拿到手之后，按这 5 步核对

1. **把链接当密码**。订阅链接等同于账号凭证，别发群里、别放截图里，细节见 [订阅链接安全](/knowledge/dingyue-lianjie-anquan/)。
2. **照着教程导入**。步骤和每一步的常见报错见 [Clash Verge 导入订阅](/tutorials/clash-verge-daoru-dingyue/)，界面文案随版本会有出入，以你看到的为准。
3. **看节点列表是否完整**。有的机场会把“剩余流量”“到期时间”做成不能用的信息型节点，这是正常现象，别当成节点失效。
4. **设置合理的更新间隔**。太勤没必要，太懒会错过节点变动，参考 [订阅更新频率](/tutorials/dingyue-gengxin-pinlv/)。
5. **更新失败先分清是谁的问题**。链接被重置、套餐过期、需要走代理才能更新、格式不匹配，都有可能，排查顺序见 [订阅更新失败怎么办](/troubleshooting/dingyue-gengxin-shibai/)。

另外，用浏览器直接打开订阅链接，看到一大串乱码并不一定是出错，通用订阅常常就是编码过的文本，不是 YAML。

## 进阶：订阅一更新，你的改动为什么就没了

很多人第一次自己加规则，几天后发现规则消失了，以为是客户端的 bug。其实这是订阅机制的正常行为，理解它，能省掉大量折腾。

订阅更新的本质，是客户端把机场提供的整份配置重新下载一遍，然后用新内容替换本地的旧内容。你直接在这份文件里手写的规则，不在机场的版本里，被覆盖是必然的。所以改动不要写进被订阅管理的那份文件，而要放进客户端提供的叠加层。多数 Mihomo 系客户端有覆写、扩展配置或脚本一类的功能：它们的思路是在每次更新之后，按你的设定把自定义规则或策略组重新叠加上去，具体叫什么名字、怎么写，随客户端和版本而异，以各项目官方说明为准。

写规则时再记住两个边界。其一，规则一般按从上到下的顺序匹配，先命中的先生效，所以你加的规则要放在默认规则的前面，才不会被兜底规则抢先。其二，配置里用到的字段和协议类型必须被你当前的内核认识。机场更新了配置，用了旧内核不认识的新字段，常见表现是整份配置加载失败或部分节点被跳过。遇到这种情况，先升级内核和客户端，再判断是机场的问题还是本地的问题。

还有一点容易被忽略：叠加层越复杂，排查越难。建议每次只改一处、改完验证一次，并且把改动记在备忘录里。出了问题，把叠加层整个关掉，用机场原版配置对照一下，能更快判断问题出在哪一边。这种“先回到原版”的习惯，比任何高级技巧都管用。

## 导入之后的 10 项自查清单

订阅导入成功，只是起点。下面这份清单可以直接勾选，把“能打开”和“真的配置对了”区分开。系统代理不生效的情况，单独见 [Clash 系统代理无效怎么办](/troubleshooting/clash-xitong-daili-wuxiao/)。

- [ ] 客户端和内核都是从项目官方仓库或官方渠道下载的，不是来路不明的安装包。
- [ ] 订阅链接没有出现在任何聊天记录、截图或公开笔记里。
- [ ] 节点列表导入后数量合理，没有一整组节点缺失。
- [ ] 能分清哪些是“剩余流量”“到期时间”这类信息型节点，不会把它们当作可用节点去连。
- [ ] 订阅更新间隔已经设置，既不是每几分钟一次，也不是长期不更新。
- [ ] 日常使用的是规则模式，全局模式只在排查问题时临时打开。
- [ ] 国内常用站点确认是直连的，没有被误绕到海外节点。
- [ ] 自定义规则写在覆写或脚本里，而不是直接改被订阅管理的文件。
- [ ] 同一台电脑上只有一个软件在修改系统代理，没有两个客户端互相覆盖。
- [ ] 已经记下机场的退款截止日和套餐到期日，并计划用一周后再决定续费。

清单里的第 7 项很多人没做：节点能连、网页能开，不代表国内流量没被绕出去。确认的办法是打开客户端的连接面板，看国内站点命中的是直连规则还是某个节点，这件事花不了一分钟。

## 术语对照：订阅、节点、模式这几个词别混着用

读 Clash 相关的教程和机场文档，几个词会反复出现。把它们摆平，后面的排查会顺很多。

- **订阅链接**：机场给你的一个网址，客户端从它拉取节点和配置，相当于账号凭证，详见术语页 [订阅链接](/glossary/subscription-link/)。
- **节点**：订阅里的每一条服务器入口，节点名只是机场的标注，真实出口以连上后的 IP 查询为准，术语页见 [节点](/glossary/proxy-node/)。
- **规则模式与全局模式**：前者按规则分流，后者让全部流量走代理，二者的取舍见 [全局模式与规则模式](/glossary/global-vs-rule-mode/)。
- **TUN 模式**：通过虚拟网卡接管流量，适合不读系统代理的程序，权限要求和冲突点见 [TUN模式](/glossary/tun-mode/)。
- **策略组**：配置里把多个节点打包成一个“可选项”的结构，常见有手动选择、自动选优、故障转移几种，不同类型的行为差别很大，选哪种要看你的用途。
- **内核与客户端**：内核负责转发，客户端负责界面和管理，两者的版本要对得上，协议是否被支持由内核决定。
- **信息节点**：有的机场把剩余流量、到期时间做成列表里的伪节点，只用来显示信息，不能连接，看到它们别当成节点失效。
- **订阅更新**：客户端重新从订阅地址拉取整份配置并替换本地内容，所以直接写在被订阅管理的文件里的改动会被覆盖。

这些词在不同客户端里的叫法会略有出入，界面文案和功能名称以你实际用的版本为准。

## 页面下方的品牌为什么这么少

## 今天就能做的 4 件事

1. 先装一个仍在维护的客户端，从官方仓库下载，不碰第三方下载站。
2. 选机场时先看订阅格式和协议，再看线路资料，最后看价格；第一次买建议先月付，别急着年付。
