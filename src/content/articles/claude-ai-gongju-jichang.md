AI开发环境网络，指的是你写代码时用到的 Claude、Cursor 这类 AI 编辑器、命令行 Agent 和 API 调用所依赖的网络出口。先说结论：它和“打开网页聊天”不是一回事——开发场景有长连接、流式输出，命令行和编辑器还不一定读系统代理。搭好它只需要三件事：出口固定、分流到位、有兜底（TUN 或环境变量）。这篇只讲方法，不会说任何品牌可用，也没有人能替你打包票。

## 开发场景和网页聊天，到底差在哪

| 场景 | 典型工具 | 网络特点 | 常见问题 |
|---|---|---|---|
| 浏览器网页 | 各家 AI 的网页端 | 走系统代理即可 | 地区不支持、IP 被风控 |
| AI 编辑器 | Cursor 等基于编辑器的产品 | 可能有自己的代理设置，也可能不跟随系统 | 流式响应中断、更新或登录失败 |
| 命令行 Agent | Claude Code、Codex 类工具 | 通常读环境变量，不读系统代理 | 连接超时、连接被重置 |
| SDK 与脚本 | 你自己写的 API 调用 | 取决于代码里 HTTP 客户端的代理设置 | 超时、证书错误 |

各工具是否支持代理、支持哪种协议（HTTP 还是 SOCKS），以官方文档为准。拿不准时优先用 HTTP 代理端口，多数客户端提供的“混合端口”两种都能接。

## AI开发环境网络对机场的 3 条要求：出口、固定与稳定

**第一，出口地区在官方支持范围内。** Claude 有自己的支持地区列表，Cursor 这类产品背后调用的模型提供方，也可能各有地区策略，都以官方页面为准，列表会更新。想让“Claude可用”，第一步是核对出口 IP 的国家，别看节点名。同类思路见 [ChatGPT机场推荐](/guides/chatgpt-jichang-tuijian/)。

**第二，出口尽量固定。** 开发时一个会话可能持续很久，出口 IP 来回变，既容易触发风控，也会让长连接断掉。IP 类型和共用度的概念见 [原生IP机场是什么](/guides/yuansheng-ip-jichang/)。

**第三，稳定性比峰值速度重要。** 流式输出对带宽要求不高，对抖动和丢包很敏感；编码补全类功能还对延迟敏感。延迟高一点，只是首字慢；断线才是真影响。至于怎么判断，见 [稳定机场怎么判断](/guides/wending-jichang-zenme-pan/)。

## 规则分流：让 AI 域名走固定节点

开发者最该学会的一招：别让所有流量走同一个自动选优的策略组，而是把 AI 相关的域名单独拎出来，指向一个手动选定的节点。思路是三步：

1. 建一个策略组，类型选手动选择（select），出口不会自己切换。
2. 把 AI 相关域名的规则指向这个组。
3. 其余流量按你日常的规则走，国内服务保持直连，别让它们绕一圈出海。

下面是示意配置，域名和节点名都是占位，不是任何真实服务的域名，请替换成各产品官方文档列出的域名和你订阅里真实存在的节点名：

```yaml
proxy-groups:
  - name: AI-固定
    type: select          # 手动选择，出口不会自动切换
    proxies:
      - 节点-示例-1
      - 节点-示例-2

rules:
  - DOMAIN-SUFFIX,ai-service-a.example,AI-固定   # 占位域名
  - DOMAIN-SUFFIX,ai-service-b.example,AI-固定   # 占位域名
  - MATCH,你的默认策略组     # 其余流量按你日常的策略走
```

不要用自动测速选优、故障转移或负载均衡类的策略组承载 AI 流量，它们会在后台悄悄换出口。AI 产品用到的域名不止一个，也会变，客户端里的连接或日志面板能看到某个请求实际命中了哪条规则，漏了域名就补上。规则集、策略组的完整入门见 [分流规则怎么设](/tutorials/mihomo-fenliu-guize/)。

## 命令行和编辑器不走代理，怎么兜底

按成本从低到高，有三种办法：

**办法一：环境变量。** 多数命令行工具会读 HTTP_PROXY、HTTPS_PROXY 一类变量，是否读取以工具文档为准。端口以你客户端里显示的为准，下面是示意：

```bash
export https_proxy=http://127.0.0.1:<端口>   # <端口> 换成客户端里显示的混合端口
export http_proxy=http://127.0.0.1:<端口>    # 127.0.0.1 表示本机
export no_proxy=localhost,127.0.0.1          # 本机地址不走代理
```

Windows PowerShell 里写法类似，用 `$env:HTTPS_PROXY` 这样的形式设置，只对当前窗口生效。

**办法二：工具自带的代理设置。** 一些 AI 编辑器在设置里提供代理地址、HTTP 版本兼容等选项，名称随版本变化，以各产品文档为准。流式响应老是中断时，可以看看有没有这类选项。

**办法三：TUN 模式。** 通过虚拟网卡接管全部流量，连不读代理设置的程序也能走代理。代价是需要管理员权限，并且可能和其他网络软件冲突，见 [TUN 模式是什么](/tutorials/tun-mode-setup/) 和术语页 [TUN 模式](/glossary/tun-mode/)。

另外，WSL、Docker 容器里的“本机地址”指向的是它们自己，不是宿主机，需要按各自文档设置宿主机地址或网络模式，这是开发者最常见的暗坑。

## 一张表看懂：三种兜底办法，生效范围和代价各是什么

上面讲了三种让命令行和编辑器走代理的办法。它们不是“越高级越好”的关系，而是各有适用范围和代价，对着下面这张表选，比凭感觉强。

| 办法 | 生效范围 | 需要什么 | 主要代价或风险 | 更适合谁 |
|---|---|---|---|---|
| 环境变量 | 只对当前终端窗口及其启动的进程，且工具要愿意读取 | 知道客户端的本地端口，会写几行命令 | 新开窗口要重设，写进配置文件后容易忘记，换网络后可能忘了关 | 主要在命令行里工作的人 |
| 工具自带的代理设置 | 只对这一个工具 | 在该工具的设置里填地址 | 每个工具各设一遍，名称随版本变化 | 只有一两个工具需要代理的人 |
| TUN 模式 | 整台电脑的流量，包括不读代理设置的程序 | 通常需要更高的权限，客户端要支持 | 可能与安全软件或其他虚拟网卡冲突，国内流量处理不当会绕远路 | 工具多、来源杂，想一次覆盖的人 |

选择的思路可以压缩成一句话：**能用范围小的，就别用范围大的**。只有一个命令行工具连不上，先用环境变量；一个编辑器的流式响应老是中断，先看它自带的代理选项；只有当你同时有多个不读代理设置的程序要处理，才值得上 TUN。范围越大，出问题时受影响的东西越多，排查也越难。

还有一个常被忽略的问题：用环境变量或工具设置指向的是你本机客户端开的端口，客户端没运行或者端口变了，工具就会报连接被拒绝。排查时先确认客户端在运行、端口和设置一致，再去怀疑节点。另外，国内的服务和内网地址别让它们走代理，用 no_proxy 之类的方式排除，否则内网访问也会被带偏。

## API中转是什么，和机场不是一回事

“API中转”这个词容易和机场混为一谈，其实完全不同：

| 对比项 | 机场 | API中转 |
|---|---|---|
| 提供什么 | 网络出口（节点订阅） | 替你转发甚至转售 API 请求的中间服务 |
| 经手的内容 | 加密的网络流量 | 你的密钥和提示内容 |
| 主要风险 | 线路质量、运营方隐私 | 密钥泄露、条款合规、返回内容是否被替换难以核实 |

机场牛不评测也不推荐任何 API 中转。如果你确实要用，请记住：密钥权限尽量收窄、定期更换，别写进订阅或规则文件里，也别发给机场客服。重要用途优先走官方或你信任的渠道。使用任何 AI 服务，都请先读官方的使用条款和支持地区说明。

## 常见报错怎么排查

| 现象 | 常见方向 | 第一步 |
|---|---|---|
| 提示所在地区不受支持，或返回类似 403 | 出口地区或 IP 的问题 | 查出口 IP 的国家，对照官方支持列表 |
| 连接超时、一直转圈 | 进程根本没走代理 | 查环境变量、工具代理设置，或开 TUN |
| 连接被重置、输出到一半断掉 | 出口切换、节点抖动 | 固定节点，换节点或换协议 |
| 证书错误 | 系统时间不对、HTTPS 被中间设备解密 | 校准时间，检查是否有抓包或解密功能开着 |
| 返回 401 | 密钥错误或权限不足，和网络无关 | 检查密钥和账号状态 |
| 返回 429 | 速率或额度限制，和网络无关 | 看官方控制台的限额 |
| 返回 5xx | 多半是服务端问题 | 看官方状态页，稍后再试 |

状态码的含义以各 API 官方文档为准。排查时先分清是“网络没通”还是“通了但被服务方拒绝”，这两类的处理方向完全不同，前者看节点和分流，后者看账号、额度和地区。

## 虚构案例：小林在 WSL 里的 AI 命令行，为什么连不上

下面是一个虚构故事，人物和过程都是举例，不对应真实用户，也没有任何测试数据，只演示“先分清是哪一层的问题”。

小林在 Windows 上写代码，日常用 WSL 跑命令行工具。他在 Windows 的浏览器里能正常访问需要的服务，但在 WSL 里启动 AI 命令行工具，却一直提示连接超时。他以为是节点出了问题，换了好几个，结果都一样。

后来他停下来，按层排查。第一步，确认浏览器能用，说明节点和订阅本身没有明显问题。第二步，在 WSL 的终端里检查代理环境变量，发现根本没设：他之前只在 Windows 的 PowerShell 里设过，而环境变量只对设置它的那个窗口生效，WSL 是另一个环境。第三步，他在 WSL 里补设了环境变量，地址写的是 127.0.0.1，却仍然连不上。他这才想起：在 WSL 里，127.0.0.1 指的是 WSL 自己，不是 Windows 宿主机，要填的是宿主机在 WSL 看来的地址，具体怎么取，随 WSL 的网络模式和版本而不同，以微软官方文档为准。

第四步，他还要确认客户端是否允许来自本机以外的连接，以及防火墙有没有拦截。这几项设置的名称随客户端和版本变化，以各自的官方说明为准。把地址、监听范围、防火墙三处都对上之后，他再用 IP 查询页确认出口，然后才实际运行工具。

这个故事里最值得记住的，是排查的顺序：**浏览器能用，说明节点大概率没问题；命令行不能用，先查它有没有走代理，再查走的是哪个地址**。而不是上来就换节点。容器、虚拟机里的情形同理，“本机地址”都指向它们自己。出口固定与分流的写法，可以回头看 [分流规则怎么设](/tutorials/mihomo-fenliu-guize/)。

## 搭完之后的 10 项自查清单

下面这份清单比文末的落地清单更细，适合搭完之后逐条验证，每一条都是一个能核对的动作。

- [ ] 我在官方页面核对过支持地区，确认自己打算使用的出口地区在其中。
- [ ] 我建了一个手动选择类型的策略组承载 AI 相关域名，而不是自动选优或故障转移。
- [ ] 我从各产品的官方文档里查了它们用到的域名，并写进了规则，没有凭记忆填。
- [ ] 我用客户端的连接面板确认过，AI 请求命中的是这条规则，而不是兜底规则。
- [ ] 终端里的代理环境变量已设置，并且在每种终端环境里分别验证过，包括 WSL 或容器。
- [ ] 我设置了 no_proxy 之类的排除项，本机地址和内网地址不会被带去代理。
- [ ] 我用 IP 查询页核对了出口国家和城市，没有只看节点名。
- [ ] 我实际运行了一次工具，观察了较长的流式输出有没有中途断掉。
- [ ] 密钥只放在我自己的环境变量或密钥管理里，没有写进订阅、规则或聊天记录。
- [ ] 我没有把机场节点放进服务器或持续集成环境，并且了解自己套餐的设备数与条款。

清单里第 9 条看起来和网络无关，却最重要：网络问题最多让你连不上，密钥泄露则可能直接带来经济损失。

## 术语对照：端口、变量、策略组、出口

读开发者文档时，下面几个词会反复出现，分清它们能少走很多弯路。

- **混合端口**：客户端在本机开的一个监听端口，同时接受 HTTP 和 SOCKS 两种代理请求，环境变量里的端口号填的就是它，具体数字以客户端界面显示为准。
- **环境变量**：写在终端环境里的设置，只对设置它的窗口及其子进程生效，命令行工具是否读取要看工具文档。
- **策略组**：配置里把多个节点打包成一个选项的结构。手动选择类型的出口不会自己切换，自动选优和故障转移类型会在后台换出口。
- **出口节点（落地节点）**：流量最终从哪里出去，决定了平台看到的 IP，概念见 [落地节点](/glossary/exit-node/)。
- **原生IP**：描述 IP 注册地与使用地是否一致，不等于住宅类型，概念见 [原生IP](/glossary/native-ip/)。
- **全局模式与规则模式**：前者让全部流量走代理，后者按规则分流，开发场景一般用规则模式，见 [全局模式与规则模式](/glossary/global-vs-rule-mode/)。
- **流式输出与长连接**：AI 工具一边生成一边返回内容，依赖一条持续的连接，对抖动和中途切换出口特别敏感。

这些词在不同工具里叫法会有出入，以各自的官方文档为准。

## 开发者选机场，看这 6 项

1. 能不能固定节点、自定义规则，这决定上面的方案能不能落地。
2. 节点地区分布里，是否包含官方支持的地区，并且不止一个，方便备用。
3. 协议与客户端内核是否匹配，见 [Clash机场推荐](/guides/clash-jichang-tuijian/) 里对订阅格式和协议的核对方法。
4. 套餐的设备数和使用条款，是否允许你在笔记本、台式机之间切换。
5. 晚高峰和抖动方面的资料，以及客服对问题的响应。
6. 能否月付、退款条款如何，先用一个月再决定。

别把机场放到服务器或持续集成环境里跑自动化流量，多数套餐面向个人终端，既可能违反条款，也不利于稳定。横向看资料可以去 [机场推荐排行榜](/rankings/) 和 [机场库](/airports/)，页面下方数据块列的是资料里记录了海外节点的品牌，不是任何服务可用的证明。

## AI开发环境网络落地清单：从零搭出可用的开发网络

1. 核对：官方支持地区页面里，你打算使用的出口地区在不在。
2. 固定：建手动选择的 AI 策略组，把 AI 域名规则指向它。
3. 兜底：命令行用环境变量，不行再开 TUN，WSL 和容器单独处理。
4. 验证：用 IP 查询页确认出口，再实际跑一次工具，观察流式输出是否中断。
5. 观察：几天内留意不同时间段的表现，节点变差就换同地区的另一个。

地区支持、使用条款和工具行为都会变化，一切以各服务方和工具的官方文档为准。使用 AI 服务请遵守所在地法律法规与服务条款，机场牛不提供法律意见。
