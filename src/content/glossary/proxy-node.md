节点是机场世界里最常被说、也最容易被说混的词。**一句话版本：你在客户端里点选的每一个条目，就是一个节点。** 但这个条目背后到底是什么，值得拆开看一下。

## 同一个词，两层意思

- **服务器那一层**：服务商在香港、日本、美国等地区部署的机器，负责接收你的流量并转发出去。
- **配置那一层**：客户端列表里的一条记录，告诉软件去连哪台机器、用什么方式连。

日常交流里两层经常混着用。比如“节点挂了”，可能是机器真的出了故障，也可能只是你本地的那条配置过期了。判断问题在哪一层，是排错的第一步。

## 一条节点配置里装了什么

| 字段 | 作用 | 说明 |
|---|---|---|
| 服务器地址 | 连到哪里 | 可能是域名，也可能是 IP；有中转时填的是入口地址 |
| 端口 | 连哪个窗口 | 参见 [多用户端口](/glossary/multi-user-port/) 的两种部署 |
| 协议 | 用什么方式说话 | 如 [VLESS](/glossary/vless/) 等，决定客户端是否支持 |
| 凭据 | 证明你是谁 | 密码或 UUID，通常随订阅下发，要保密 |
| 传输与加密参数 | 握手和伪装的细节 | 随协议不同而变化，别手动乱改 |
| 名称 | 给人看的标签 | 由服务商自己写，不代表经过核实 |

这些字段一般不需要你手填：服务商把它们打包进订阅，客户端导入后自动生成，见 [订阅链接](/glossary/subscription-link/)。

## 节点名字里的标签，该怎么读

节点名称通常带有地区、线路类型、倍率等信息，例如“香港 01”“中转”“x2”这类写法。读的时候留意两点：

- **名称是服务商自己命名的**，写“专线”“原生”并不等于经过第三方核实，核对方法见 [IPLC](/glossary/iplc/) 与 [原生IP](/glossary/native-ip/)。
- **倍率标注直接影响扣费**，同样用一份流量，节点不同，消耗可能不同，详见 [流量倍率](/glossary/traffic-multiplier/)。

## 节点、服务器、线路，是什么关系

三个词常被并列提起，其实不在一个层面：

- **服务器**是硬件资源，一台服务器可以开多个端口、跑多种协议，从而对应多条节点。
- **节点**是服务器上的一个可用入口，加上连接它所需的全部参数。
- **线路**描述的是流量走的路径，比如是否经过 [中转线路](/glossary/relay-route/)，最后出口在哪个 [落地节点](/glossary/exit-node/)。

所以“香港节点”这个说法只告诉你地区，并没有说明线路类型、带宽和共用人数。整体关系图可以看 [机场节点是什么](/knowledge/jiedian-dingyue-xieyi-guanxi/)，从零理解整套概念可以先读 [机场是什么](/knowledge/what-is-jichang/)。

## 节点“不通”时，先查哪几处

1. **只有一两个不通**：多半是那几台服务器或线路的问题，换别的节点即可，成因见 [部分节点能用](/troubleshooting/bufen-jiedian-keyong/)。
2. **全部都不通**：先怀疑本地网络、系统时间、订阅是否过期，再回头查节点，步骤见 [机场节点超时](/troubleshooting/jiedian-quanbu-chaoshi/)。
3. **延迟测试通过但打不开网页**：测试只说明连得上，不说明其后的链路都通畅，别把它当成速度或可用性的结论。

另外提醒：节点列表是服务商维护的，增删改都属正常。想保持列表最新，按合理频率更新订阅即可。使用相关服务请遵守所在地法律法规，机场牛不提供法律意见。
