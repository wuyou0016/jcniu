白名单和黑名单经常被说反，所以先定下基本规则：**白名单是“只放行名单里的”，黑名单是“只拦截名单里的”。** 前者更严格，后者更宽松，用途完全不同。

## 白名单IP是怎么工作的

服务端检查每个访问请求的**来源 IP**：

1. 来源在名单里，放行。
2. 来源不在名单里，拒绝或直接丢弃。

所以白名单管理的是“谁能进门”，而不是“谁做了什么”。它是一种限制手段，不是万能防护。

## 在机场相关场景，会碰到的三种情况

| 场景 | 谁在设白名单 | 对你的影响 |
|---|---|---|
| 目标服务限制来源 IP | 公司系统、内部平台、部分 API 服务 | 你通过节点访问时，对方看到的是节点 IP，不在名单里就被拒 |
| 订阅或面板的访问限制 | 服务商 | 换网络或换设备后，可能被提示异常，具体以服务商说明为准 |
| 自建节点的防火墙 | 你自己 | 只放行自己的 IP，能降低被扫描的概率，但换网络要记得改名单 |

## 为什么共享出口和白名单不太合得来

白名单要求来源地址**稳定、可预测**，而机场的 [落地节点](/glossary/exit-node/) 通常有这些特点：

- 同一出口 IP 往往由很多用户共用。
- 出口 IP 可能因为维护、更换机房而变化。
- 服务商一般不会公开固定的出口地址清单。

所以把节点 IP 加进别人的白名单，常常不靠谱：今天能用，明天就失效了。

## 需要固定出口 IP 时，有几种思路

1. **让相关服务直连**：用规则模式让这个服务走你本地的真实网络，见 [全局模式与规则模式](/glossary/global-vs-rule-mode/) 与 [分流规则](/tutorials/mihomo-fenliu-guize/)。
2. **问服务商是否有固定 IP 或独享 IP 的方案**：这类方案通常需要额外付费，是否提供以官方说明为准。
3. **考虑自建**：自己控制出口地址，但要承担部署和维护成本，对比见 [机场和自建节点](/knowledge/jichang-vs-zijian/)。
4. **开发场景的 API 调用**：先看目标 API 是否真的要求 IP 白名单，再决定方案，思路见 [AI开发环境网络](/guides/claude-ai-gongju-jichang/)。

## 几条安全提醒

- **别把白名单当成唯一防护**：IP 之外，账号、密钥、权限同样要管好。
- **订阅链接也要保密**：它相当于账号凭证，见 [订阅链接](/glossary/subscription-link/)。
- **不要为了方便把管理端口对所有地址开放**：自建时尤其如此。
- **别人让你把节点 IP 加进白名单**，先弄清对方是谁、为什么，再动手。

白名单与 [原生IP](/glossary/native-ip/) 不是一回事：前者是访问控制，后者是 IP 的类型。隐私与账号的整体建议见 [机场安全吗](/warnings/jichang-anquan-yinsi/)。使用相关服务请遵守所在地法律法规，机场牛不提供法律意见。
